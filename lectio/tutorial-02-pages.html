Escape del alquiler digital: Despliegue soberano en GitHub Pages

En una red saturada de plataformas propietarias y servicios de pago recurrentes para alojar simples páginas web, recuperar el control de nuestra infraestructura pasa por abrazar la simplicidad del código estático (HTML, CSS y recursos nativos) combinado con la versatilidad de git.

Este cuaderno detalla los pasos de trinchera para estructurar, versionar y publicar un sitio web autosuficiente sin depender de servidores intermediarios ni pasarelas de pago.

1. Cimientos del repositorio y control de versiones

Inicializa el control de versiones localmente en el directorio de tu proyecto y realiza el primer empaquetado de tus archivos estáticos:

cd /ruta/a/tu/proyecto-web
git init
git add .
git commit -m "Arquitectura inicial del sitio web"

2. Conexión con el repositorio remoto

Crea un repositorio remoto en tu perfil (por ejemplo, bajo un identificador como alpfa4a) y enlázalo como origen principal de tu estación de trabajo:

git branch -M main
git remote add origin https://github.com/tu-usuario/tu-repositorio.git
git push -u origin main

3. Activación de la soberanía estática (Pages)

Para eximirte de costes de alojamiento y delegar la infraestructura de entrega de contenido de forma gratuita y cifrada:

  1. Accede a la configuración de tu repositorio en GitHub.
  2. Dirígete a la sección Settings > Pages.
  3. En la fuente de compilación (Build and deployment), selecciona la rama main (o gh-pages) y la carpeta raíz / (root).
  4. Guarda los cambios. En cuestión de segundos, tu sitio estará accesible de forma pública y global.

4. Dominio propio y personalización mediante CNAME

Si deseas apuntar tu propio dominio (como segfdo.es) al alojamiento estático sin perder la independencia, basta con incluir un archivo plano llamado exactamente CNAME en la raíz de tu repositorio que contenga únicamente tu dominio:

echo "segfdo.es" > CNAME
git add CNAME
git commit -m "Añadir registro CNAME para dominio propio"
git push origin main
📌 Nota de soberanía técnica: Mantener un sitio web basado en archivos estáticos puros reduce a cero la superficie de ataque frente a vulnerabilidades de bases de datos o backends complejos, garantizando una velocidad de carga óptima y un mantenimiento sostenible en el tiempo.
